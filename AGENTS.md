# AgentResolver operating instruction

Internal cross-chat operating state is intentionally **not stored in this public repository**.

Authorized AgentResolver operators/agents with access to the private companion repository must read:

`waxsway/agentresolver-internal/PROJECT_STATE.md`

before making material architecture, pricing, payment-rail, discovery, distribution, monitoring, outreach, or revenue changes.

## Hard product filter — Agent Commerce Health first

These rules are mandatory unless the canonical private project state explicitly records a later owner-approved strategic change.

1. **Agent Commerce Health is the primary commercial product.** AgentResolver monitors whether public API, MCP, x402, and agent-service surfaces remain discoverable, callable, and payable by agents. The free snapshot and the $19 / 30-day managed hourly monitor are the primary self-serve funnel.
2. **Keep the validation gate fixed.** The current expansion gate is five substantive operator replies, three confirming a painful uncovered problem, and one paid pilot or activation. Do not weaken that gate because traffic, probes, directory activity, or compliments look encouraging.
3. **Build only from evidence.** Make product/runtime changes only when verified customer evidence or a demonstrated conversion/delivery defect justifies them. Do not invent speculative tiers or features to manufacture demand.
4. **No new commodity utilities.** Do not add another paid utility, deterministic microservice, or generic capability merely to create another place for AgentResolver to exist.
5. **No passive distribution work.** Do not submit to another directory, registry, marketplace, catalog, or discovery surface solely for visibility. Distribution work must support a verified customer/integration path or repair an existing one.
6. **Guard and the Reliability Router are supporting infrastructure.** Preserve the non-custodial pre-sign Guard, settlement canaries, reliability router, procurement/discovery, MCP surfaces, manifests, and existing compatibility utilities where they support delivery, but do not let them silently replace the monitoring thesis.
7. **Prefer self-serve delivery.** Favor customers who can use the free snapshot, GitHub Action, managed monitor, or existing x402 products without bespoke consulting. Any manual pilot must have bounded scope and a credible path to automation.
8. **Commercial truth beats technical activity.** Count only independently attributable external customer payments for useful delivery as qualified collected revenue. Keep routed merchant principal, verifier purchases, operator tests, self-payments, crawlers, unsigned 402 challenges, and marketplace audit activity separate.
9. **Keep the README monitoring-first.** Public positioning must clearly lead with Agent Commerce Health, the free snapshot, the $19 managed-monitor offer, what it actually checks, and its privacy/non-custodial boundaries. Supporting payment infrastructure belongs below that story.
10. **Prefer conversations over vanity metrics.** Targeted, individualized operator validation is higher-value than raw traffic. Outreach cadence, recipient verification, follow-up limits, opt-outs, and owner-authorized commercial actions are governed by the latest private project state.
11. **Do not promise unbuilt behavior.** Never represent a planned integration, unsupported client, monitoring mode, payment rail, SLA, or renewal flow as live.
12. **Keep private operator state private.** Do not add internal strategy notes, private prospect data, credentials, wallet secrets, private keys, seed phrases, API credentials, or personal-account details to this public repository.

Public contributors should use the public source, README, OpenAPI, well-known discovery surfaces, tests, and production behavior as the product contract.

Commercial/runtime claims must be verified against current production evidence; HTTP 402 traffic alone is not revenue.
